Да, тут уже видно, в чем принципиальное отличие от рабочего случая.
У тебя TUN-интерфейс создается, но маршрутизация через него вообще не настраивается.
Сравним.

Рабочий sing-box
Появляется интерфейс:

44  sing-tun Tunnel

Появляется адрес:

172.18.0.1

Появляется маршрут сети TUN:

172.18.0.0/30 -> On-link

И самое главное — появляется новый default route:

0.0.0.0/0 -> 172.18.0.2

Именно он заставляет Windows отправлять весь трафик в TUN.





Твой Xray

Появляется интерфейс:

53 Xray Tunnel

Но дальше происходит странное.

Вместо нормального адреса интерфейс получает:

169.254.194.73

Это адрес из диапазона 169.254.0.0/16 (APIPA).

Windows выдает такой адрес, когда:

интерфейс поднялся;
но никто не назначил ему нормальный IP.

То есть фактически получилось примерно так:

Xray создал TUN
↓
Windows ждала настройки
↓
никто не присвоил IP
↓
Windows выдала APIPA 169.254.x.x






И из-за этого отсутствуют:

❌0.0.0.0/0 -> TUN

❌172.x.x.x/30

❌вообще любой маршрут через этот интерфейс.

Поэтому остается единственный default route:

0.0.0.0/0 -> 192.168.1.1

и весь трафик идет напрямую.
